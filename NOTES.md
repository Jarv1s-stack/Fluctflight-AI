## Архитектура сцены (main.js)
Слои в `group`:
1. `buildShell()` — точечная решётка Фибоначчи, R=1.72, 11000 точек (7200 на мобильных),
   яркость по rim (лимб ярче), аддитивный блендинг.
2. `buildFilaments()` — 480 нитей × 66 сегментов, LineSegments. Пути строятся на CPU
   через curl-noise (`curl()` на базе `fbm`/`noise3`). Ключевые параметры:
   `scale = 2.0 + rand^1.4 * 5.2`, `step = 0.010..0.026`, тангенциальный биас 0.22,
   удержание внутри R=1.28. Анимация — смещение snoise во вершинном шейдере.
3. `core` — Points из одной точки, halo+hot в фрагментном шейдере, пульс от `uPulse`.
4. `buildSparks()` — 1500 искр, 24% снаружи оболочки, 5.5% красных, мерцание.
5. 3 кольца памяти (`buildRing`) — дуговая маска яркости, не полные окружности.
6. 5 глитч-полос (плоскости со scanline-шейдером), вспыхивают случайно, чаще при высоком chaos.

Постобработка: RenderPass → UnrealBloomPass(strength=uGlow, radius 0.42, threshold 0.42)
→ ShaderPass (хроматическая аберрация + виньетка + зерно) → OutputPass. ACESFilmic, exposure 1.05.

## Важные решения / грабли
- **Размер точек**: считается физически — `gl_PointSize = worldSize * uProj / -mv.z`,
  где `uProj = h*pixelRatio / (2*tan(fov/2))` пересчитывается в `onResize()`.
  Ранняя версия с магическими константами (150/-mv.z) давала блобы по 100+ px.
- **Пересвет**: threshold блума 0 + аддитивные слои = белый экран. Держать threshold ≥ 0.4
  и низкие альфы (нити: `0.13 + uChaos*0.26`).
- **Кадрирование**: `computeFit()` считает дистанцию по МЕНЬШЕМУ из v/hFOV (R=1.92),
  чтобы на портретных экранах сфера не вылезала. Зум пользователя сохраняется по отношению.
- На мобильных панель параметров стартует свёрнутой (`SMALL` = min(w,h) < 720).

## UI
Слайдеры: Активность (uChaos), Свечение (bloom.strength), Плотность нитей (uDensity,
мягкая отсечка по `aId`), Пульс ядра (uPulse). Чекбоксы: автовращение, оболочка.
Пресеты: Покой / Мышление (дефолт) / Перегрузка — анимированный твин 1.5 ед/с.

Кластер сдвинут по `group.position.x = -1.6` (было -1.2), чтобы освободить правую
часть экрана под панель чата.

## AI-чат (chat.js)
Панель `.hud--chat` справа, симметрично параметрам слева. Логика полностью на клиенте,
без бэкенда:
- **Текст** — OpenRouter (`openrouter.ai/api/v1/chat/completions`), модель
  `nvidia/nemotron-3-nano-30b-a3b:free`, история диалога хранится в памяти вкладки.
  OpenRouter поддерживает прямые вызовы из браузера (CORS + заголовки
  `HTTP-Referer`/`X-Title` для атрибуции), бэкенд не нужен.
- **Голос ИИ** — `speechSynthesis` (Web Speech API): бесплатно, без ключа, работает
  во всех современных браузерах. Голос подбирается эвристикой: сначала `ru`-голос
  с "Google/Natural/Online" в имени (обычно самый качественный), иначе любой `ru`,
  иначе системный дефолт.
- **Голосовой ввод** — `SpeechRecognition` (`webkitSpeechRecognition`): тоже бесплатно,
  но поддержан только в Chrome/Edge — на остальных браузерах кнопка микрофона
  автоматически становится disabled, текстовый ввод работает всегда.
- **Синхронизация с голосом** — событие `utterance.onboundary` даёт `charIndex` почти
  на каждое слово: по нему (а) текст в чате открывается печатной машинкой синхронно
  с голосом, (б) дергается `window.Fluctlight.pulse()`. У части движков синтеза
  `boundary` не стреляет вовсе — на этот случай есть запасной интервал-пульс раз в
  260мс, чтобы куб не был "немым" даже без точной тайминг-инфы.
- **Мост в сцену** — `window.Fluctlight = { pulse(), setSpeaking(), setListening() }`
  определён в main.js (не в chat.js), примешивается к `uPulse`/`uChaos`/`bloom.strength`
  каждый кадр в `animate()`, поверх, а не вместо, значений от слайдеров.

### Грабли / решения
- API-ключ OpenRouter лежит в открытом виде в `chat.js` — это статический сайт без
  сервера, спрятать его некуда. Приемлемо для личного проекта, но ключ виден любому
  через "просмотр кода". Если сайт станет публичным — вынести вызов на прокси-бэкенд
  и ротировать ключ.
- Прямого доступа к amplitude/waveform у `speechSynthesis` нет ни в одном браузере
  (в отличие от `<audio>` + `AnalyserNode`), поэтому синхронизация анимации с голосом —
  приближение через `boundary`/`start`/`end`, а не честный анализ звука.
